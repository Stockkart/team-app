# @stockkart/attendance-protocol

**Status:** Active

**App copy (worker-app D17, DD21).** This package is the Stockkart Team app's copy of `inventory-platform/platform/attendance-protocol`; the web keeps the other copy for `core/hr`. `src/**` and `fixtures/**` are byte-identical in both: `node scripts/protocol-parity.mjs` at this repository's root (`pnpm check:protocol`) checks it against `$INVENTORY_PLATFORM_DIR/platform/attendance-protocol` (default `../inventory-platform`). Change both copies, platform first, then this one; only `package.json`, `vite.config.mts`, `eslint.config.mjs` and this README differ (package name `@stockkart/attendance-protocol`, consumed by the app as `workspace:*`). The Java fixtures (`fixtures/phones.json`, `fixtures/canonical.json`) come from `inventory-api`, the source of truth, and are copied here unchanged.

Wire types and pure helpers shared by the Stockkart Team app (this repository's root) and the manager HR UI (`inventory-platform/core/hr`) for the biometric attendance feature (`.kiro/specs/HR-module`) and Stockkart Team (`.kiro/specs/worker-app`). Pure TypeScript: no React, no fetch, no browser or React Native API.

## Owns

- `src/types.ts` — mirrors of the `inventory-api` `core/hr` DTOs for the app endpoints (`ClaimPairingRequest`, `CompletePairingRequest`, `PairingBootstrap`, `AppStatusResponse`, `AppPunchRequest`, `AppPunchResponse`, `PunchResponse`, `PairingStateResponse`, `PairingCodeResponse`, `AppHealthResponse`) with string-literal unions for `PunchSource`, `PunchFlag`, `AttendanceSource`, `PairingStatus`, `UnpairReason`, `ManualMarkReason`, `DeviceOs`
- `fixtures/canonical.json` — generated by the Java `AppSignatures` tests in `inventory-api` (`core/hr/src/test/resources/attendance-protocol/fixtures/canonical.json`). Do not edit by hand; copy the regenerated file when the Java side changes. The TypeScript canonical builders assert byte equality against it.
- `src/canonical.ts` — `canonicalPunchPayload()` / `canonicalRequestEnvelope()` (`SKAT-PUNCH-1` / `SKAT-REQ-1`, byte-identical to Java `AppSignatures`), `sha256Hex()` (WebCrypto `crypto.subtle`, or an injected digest such as `expo-crypto` on runtimes without it), `formatPhoneTime()`, hex helpers
- `src/pairing-code.ts` — `PAIRING_CODE_ALPHABET`, `normalisePairingCode()`, `isPairingCode()`, `pairingQrPayload()`, `pairingCodeFromScan()` (QR URL `https://stockkart.in/attendance/pair#<CODE>` or bare code), mirror of Java `PairingCodes`
- `src/messages.ts` — the refusal and flag sentences the app shows word for word (`SERVER_MESSAGES` by `ErrorCode` name, `FLAG_SENTENCES`, R7.10 helpers, confirmation and offline lines)
- `src/worker.types.ts` — Stockkart Team (`.kiro/specs/worker-app`) wire types, mirrors of the `inventory-api` DTOs for `/api/v1/hr/worker/**` and `/api/v1/hr/join-requests/**` (`WorkerStateResponse`, `JoinRequestSelfResponse`, `WorkerProfileResponse`, `ShopLookupResponse`, `WorkerNotificationsResponse`, `HrNotificationResponse`, `JoinRequestRow`, `JoinRequestDetail`, `JoinRequestsPageResponse`, `JoinRequestDecision`, `BulkJoinResult` and the request bodies) with string-literal unions for `WorkerState`, `WorkerJoinStatus`, `JoinOutcome`, `HrNotificationType`, `ModuleKey` (`MODULE_KEYS`, `isModuleKey()`)
- `src/worker-messages.ts` — `ErrorCode` 8035–8047 texts word for word (`WORKER_SERVER_MESSAGES`, `WORKER_ERROR_CODE_NUMBERS`; 8042, 8043 and 8046 are unused gaps left by the removed legacy pairing flows), the worker-path text of 8028 (`TOO_MANY_ATTEMPTS_WORKER`), the two `%s` employee-code templates and `workerRefusalText()`
- `src/phone.ts` — `normalisePhone()` / `isValidPhone()`, twin of Java `PhoneNumbers.normalise` (ASCII digits only; exactly 10, or `91` + 10 → the 10 digits, else `null`)
- `fixtures/phones.json` — generated by the Java `PhoneNumbersFixtureGeneratorTest` in `inventory-api` (`core/common`). Do not edit by hand; copy the regenerated file when the Java rule changes. `phone.test.ts` asserts `normalisePhone` gives the same answer on every row.

## Boundaries

- Nx tags `type:platform`, `scope:attendance`. `scope:attendance` may depend on `scope:attendance` and `type:platform` only (root `eslint.config.mjs`).
- Nothing here may import `ui-kit`, `api-client`, `session`, `routing` or any `core/*` package: the Expo app cannot load them.

## Tests

`vite.config.mts` is test-only (vitest, node environment; fast-check from the repository root for property tests). `pnpm test` at the repository root runs it as one of its vitest projects; alone: `pnpm --filter @stockkart/attendance-protocol test` or `pnpm exec vitest run --project @stockkart/attendance-protocol`.

## Does not own

- Calling the endpoints (the app's `src/api/appClient.ts`, the web's `core/hr/src/api/pairing.api.ts`)
- The biometric signer (the app's `modules/biometric-signer`)
- Register / settings types that only `core/hr` uses (`core/hr/src/model`)
